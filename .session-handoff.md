═══ REGRAS OPERACIONAIS (as de sempre) ═══

· o sandbox bash NÃO alcança o WSL — eu edito (Read/Write/Edit), você roda e cola
· **comandos CURTOS** — linha longa quebra no terminal e o shell roda os pedaços
· **e2e roda DENTRO**: `$DC run --rm e2e-runner ts-node runner.ts --only N`
· **e2e apaga `tenant_demo:*` e `session:*`** antes de CADA cenário
  (`lib/redis-client.ts` §40) — contra o demo leva junto instâncias logadas,
  snapshots, ContextStore, claims, tokens de resume e sessões vivas
· **platform-ui não tem volume mount** — mudança de frontend exige `build`
· **teste também mora na imagem** — controle negativo por stash exige REBUILD;
  preferir teste DIFERENCIAL (as duas leituras lado a lado, afirmando divergência)
· arquivo NOVO exige `build --no-cache`; edição de existente entra no build normal
· PREVER O NÚMERO antes de rodar, e escrever a previsão. CONTAR, não estimar
· **previsão de DELTA exige a BASE contada** — senão o resultado não pode julgá-la
  (aconteceu nesta sessão)
· **preflight sobre código casa o TOKEN da chamada, não o identificador** — senão os
  comentários da própria mudança recompõem o número antigo
· veredicto RAMIFICA sobre o valor medido; três ramos, e AUSENTE é INCONCLUSIVO
· antes de comparar duas leituras, PROVAR QUE O LEITOR LÊ (e conferir o PREFIXO)
· **um contador de AUSÊNCIA precisa de um contador-TESTEMUNHA de presença ao lado**
· **`MONITOR` nomeia o CULPADO pelo IP do cliente** — mapear com
  `docker inspect -f '{{.Name}} {{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' $(docker ps -q)`
  ou `$DC exec -T <svc> hostname -i`
· **contar não é identificar** — `SCARD 1` não diz QUAL; use `SMEMBERS`
· **asserção com cláusula de escape só vale condicionada** — ler o par
· `up -d --force-recreate` APAGA o `pip install` do pytest — reinstalar antes
· o container do `redis` NÃO tem python3 — parser JSON roda no `routing-engine`
· usar `docker compose … exec -T redis`, nunca `docker exec redis`
· todo `docker exec` dentro de script interativo leva `< /dev/null`
· `docker compose exec -d` funciona para armar um `MONITOR` detached no container
· **experimento sensível a tempo roda DENTRO de um processo**
· `schemas` NÃO é serviço do compose (compila dentro do build de cada consumidor)
· ambiente = docker-compose.demo.yml, tenant `tenant_demo`,
  ClickHouse/Postgres db = plughub_demo, agent-registry em plughub_registry
